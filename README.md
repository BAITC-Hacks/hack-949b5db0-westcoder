# EventMatch — умный подбор event-подрядчиков

MVP команды **WESTcoder** для HackAlem. Подбор подрядчиков и команды для мероприятия по анонимизированному каталогу хакатона.

Команда: Nurtilek Koblandy, Meirbek Arystanov, Nurkeldi Adilov.

## Запуск

Нужен Python 3.11+. Backend использует стандартную библиотеку, установка пакетов не требуется.

Из корня репозитория:

```powershell
python -m backend.server
```

Откройте **http://127.0.0.1:8000**. Остановка — `Ctrl+C`. Другой порт: `python -m backend.server --port 8080`.

Backend и frontend обслуживаются одним процессом. Сборка frontend не нужна. При изменениях Python перезапустите сервер; при изменениях HTML/CSS/JS обновите страницу.

Рабочий интерфейс — `frontend/index.html`, его обслуживает Python-сервер. Открытие HTML напрямую или через обычный Live Server не запускает API. Корневой `index.html` содержит инструкцию запуска; `about.html` описывает проект. `Untitled-1.html` — статический предпросмотр каталога.

## Возможности

- До трёх подрядчиков по городу, дате, категории, формату, бюджету, часам работы и языку.
- Пожелания к стилю: «спокойная подача, без конкурсов» или «живая музыка, джаз».
- Сортировка по пожеланиям либо по стартовой цене.
- Объяснения, цитаты, неподтверждённые пожелания и возможные противоречия.
- Календарь числа подходящих профилей на каждый из 100 дней. Нажатие на дату запускает подбор. Изменение формы помечает старый календарь неактуальным.
- Избранное в localStorage, сравнение двух–четырёх профилей, повторная проверка сохранённого запроса. При недоступном хранилище список работает до закрытия страницы.
- Проверяемые подсказки с изменением от одного до трёх условий, применяемые только по нажатию.
- Команда из одной–пяти ролей: общая дата и бюджет, отдельные часы для каждой роли, разные подрядчики. При нехватке бюджета показывается минимальная сумма полной команды, если она существует.

## Архитектура

```text
CSV / JSON / JSONL
  → dataset.py: загрузка и нормализация в памяти
  → models.py: проверка запроса и правил датасета
  → filters.py: обязательные ограничения и воронка
  → preferences.py / semantic.py: локальная проверка пожеланий или embeddings описаний
  → scoring.py: детерминированная оценка
  → service.py: сортировка по баллу или цене, максимум 3; календарь
  → team.py: команда с минимальной общей ценой и уникальными исполнителями
  → explanations.py: объяснения из фактов
  → relaxation.py: пересчёт альтернативных условий
  → server.py: REST API
  → frontend/: HTML, CSS, JavaScript
```

Все ограничения и числовые оценки считаются локально. Для 66 записей достаточно последовательного прохода; отдельные БД каталога и векторное хранилище не требуются. SQLite используется только для опционального кэша embeddings.

## Алгоритмы

Фильтры: город → категория → доступность → формат → цена → длительность → язык. Сравнение строк без учёта регистра и лишних пробелов. Бюджет и часы проверяются включительно.

Обязательные условия проверяются до ранжирования. Пожелания не могут вернуть занятого или неподходящего по бюджету подрядчика.

В режиме пожеланий балл состоит из соответствия описанию (вес 80) и запаса бюджета (20). Без анализа описания учитывается только запас бюджета. В режиме цены порядок определяется стартовой ценой. В режиме пожеланий сортировка — `score DESC → id ASC`; в режиме цены — `price_from_kzt ASC → id ASC`. Балл не является вероятностью или рейтингом качества.

| Фактор | Вес | Балл 0–100 |
| --- | ---: | --- |
| Запас бюджета | 20 | `100 × (1 − price_from_kzt / budget_kzt)` |
| Соответствие описанию | 80 | Локальная проверка пожеланий или сходство embeddings |

Итог — сумма `балл × вес`, делённая на сумму активных весов, с округлением до двух знаков. При нулевых бюджете и цене бюджетный компонент равен 100. Если анализ описания недоступен, его вес исключается. Формат, язык и длительность проверяются обязательными фильтрами.

В деталях карточки видны компоненты оценки, веса и факты из профиля. Генеративная LLM не используется. Воронка считает каждый профиль на первом непройденном условии; подробный список показывает все нарушения. Прошедшие фильтры кандидаты ниже топ-3 указаны отдельно.

Без внешнего API используется проверка ключевых слов, небольшого словаря близких выражений и простых отрицаний. Это не полноценное понимание произвольного текста. Отсутствие слова не доказывает отсутствие услуги; такие пожелания помечаются как неподтверждённые.

При включённых embeddings ранжирование использует смысловое сходство запроса и описания. Цитаты и отметки противоречий остаются результатом локальной проверки слов, а не объяснением каждого значения embeddings.

Для команды выбирается **минимальная сумма стартовых цен**. Динамическое программирование по наборам ролей проверяет уникальность исполнителей, а не выбирает по одному самому дешёвому независимо. Сложность: `O(N × R × 2^R)`, где `R ≤ 5`. Один профиль не может выполнять две роли одновременно.

## Фактический датасет

`data/contractors.csv` — побайтовая копия пользовательского файла `hackathon dataset anonymized .csv`. Исходный файл не изменялся, новые профили не добавлялись. Имеющийся `Untitled-1.html` сохранён.

SHA-256: `6a724b6b7dfb5973343e68ba18dadb60fc807d87e3d78f03ee86fb26cb089f7d`.

| Поле | CSV → приложение |
|---|---|
| `id`, `anon_name` | Строковые ID и анонимное имя |
| `categories` | Список категорий, разделитель `\|` |
| `city` | Алматы, Астана, Зарубежье |
| `price_from_kzt` | Начальная цена за мероприятие; пустая/невалидная → неизвестна |
| `event_formats`, `languages` | Списки, разделитель `\|` |
| `max_hours` | Максимум часов; пустая строка → `None` |
| `busy_dates` | Занятые даты ISO, разделитель `\|` |
| `description` | Исходное описание |
| `synthetic`, `city_imputed`, `price_imputed` | Флаги `True`/`False` |

66 профилей, 17 категорий: Алматы — 50, Астана — 15, Зарубежье — 1. Синтетических профилей — 13; город проставлен у 8, цена у 18; пустой `max_hours` у 9. Цены: 100 000–6 000 000 ₸. Подробнее: [анализ датасета](docs/dataset-analysis.md).

Правила исходного каталога:

- Календарь: **2026-09-23 — 2026-12-31**. Вне окна API возвращает 422: отсутствие записи не подтверждает доступность за пределами известного календаря.
- Для `Флорист`, `Декоратор`, `Подарки и сувениры` пустой `max_hours` означает работу без почасового присутствия и не препятствует подбору с длительностью.
- Для остальных категорий неизвестный лимит не подтверждает запрошенную длительность и приводит к исключению. Без требования часов фильтр не применяется.
- Пустой список занятых дат — отсутствие занятости в пределах окна. Отсутствующий, `null` или повреждённый календарь — неизвестная доступность, кандидат исключается.
- Неизвестная цена не считается нулевой. Синтетические и проставленные значения помечены в интерфейсе.

Загрузчик поддерживает JSON (массив объектов) и JSONL. ID должны быть непустыми и уникальными. При замене `DATASET_PATH` нужно пересмотреть правила календаря и значение `null`, настроенные на исходный датасет.

HTML-preview содержит те же профили, что и исходный CSV.

- Цена «от» не является окончательной стоимостью. Сумма команды — ориентир без дополнительных услуг, логистики и доплат.
- Отсутствие даты в `busy_dates` означает отсутствие записи о занятости. Доступность нужно подтвердить; подбор не является бронированием.
- Контакты, подтверждённые отзывы, фотографии портфолио и полная вместимость площадок не представлены и не выдумываются.
- Избранное хранит снимок профиля и параметров запроса в конкретном браузере. После изменения каталога или условий используйте «Перепроверить подбор».

## Настройки

Опциональный семантический путь использует [OpenAI Embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create). Для внешнего анализа скопируйте `.env.example` в `.env`, задайте свой `OPENAI_API_KEY` и `ENABLE_EMBEDDINGS=true`. Не добавляйте `.env` в Git. Без этих настроек всё работает локально.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Адрес сервера |
| `PORT` | `8000` | Порт |
| `ENABLE_EMBEDDINGS` | `false` | Внешний анализ |
| `OPENAI_API_KEY` | пусто | Ключ внешнего API |
| `EMBEDDING_MODEL` | `text-embedding-3-small` | Модель embeddings |
| `DATASET_PATH` | `data/contractors.csv` | CSV, JSON или JSONL |
| `CACHE_DIR` | `.cache` | Кеш SQLite |

Ключ остаётся на сервере; `.env` исключён из Git. Внешний API может тарифицироваться провайдером. При внешнем анализе отправляются текст запроса и описания подходящих профилей. Успешные решения кешируются; сбой провайдера кешируется на пять минут, затем возможна повторная попытка. Ключ учитывает модель, каталог, запрос и состав кандидатов. Векторы кешируются по модели и тексту. Кеш проверяет структуру, конечность чисел, состав кандидатов и версию ключа; повреждённые записи не используются. Соединения SQLite явно закрываются, в том числе на Windows.

Сетевой таймаут — 6 секунд. При недоступности API, отсутствии ключа или ошибке кеша используется локальная проверка пожеланий; если пожеланий нет, остаётся бюджетный компонент. UI показывает фактический режим. При неизменных данных, настройках и кеше порядок воспроизводим. Реальный внешний провайдер без пользовательского ключа не проверяется; тесты используют подмену транспорта.

## API

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/health` | Состояние сервера |
| GET | `/api/meta` | Справочники, границы календаря и демо |
| POST | `/api/recommend` | Топ-3, объяснения, воронка, подсказки |
| POST | `/api/calendar` | Число кандидатов на каждый день |
| POST | `/api/team` | Полная команда или причина отсутствия решения |

`Content-Type: application/json`, максимум 16 KiB. Ошибки: 400 — некорректный или чрезмерно вложенный JSON; 413 — пустое или слишком большое тело; 415 — неправильный Content-Type; 422 — неверные поля. Отрицательные и бесконечные числа, boolean вместо числа и несуществующие даты отклоняются. Неизвестный город/категория даёт `category_not_found`; отсутствие подходящих профилей — `no_candidates`; успешный подбор — `matched`.

Запрос подбора или календаря:

```json
{
  "city": "Алматы",
  "date": "2026-09-26",
  "event_format": "свадьба",
  "category": "Фотограф",
  "budget_kzt": 600000,
  "duration_hours": 6,
  "language": "русский",
  "preferences": "репортаж, естественные эмоции",
  "sort_by": "style"
}
```

`duration_hours` и `language` могут быть `null`. `preferences` — до 1500 символов, по умолчанию пустая строка. `sort_by` — `style` или `price`.

Пример PowerShell:

```powershell
$eventBody = @{
  city = 'Алматы'
  date = '2026-09-26'
  event_format = 'свадьба'
  category = 'Фотограф'
  budget_kzt = 600000
  duration_hours = 6
  language = 'русский'
  preferences = 'репортаж, естественные эмоции'
  sort_by = 'style'
} | ConvertTo-Json
Invoke-RestMethod http://127.0.0.1:8000/api/recommend -Method Post -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($eventBody))
```

Ответ содержит `status`, `message`, `request`, `total_candidates` (в городе и категории), `eligible_candidates`, `recommendations`, `filter_stats`, `excluded_reasons`, `excluded_candidates`, `suggestions`, `semantic_mode`, `dataset_sha256`. В рекомендации — поля профиля, `name`, `category`, `score`, `score_breakdown`, `reasons`, `warnings`, `explanation`.

Запрос команды (`budget_kzt` — общий бюджет):

```json
{
  "city": "Алматы",
  "date": "2026-09-26",
  "event_format": "свадьба",
  "budget_kzt": 2000000,
  "language": "русский",
  "roles": [
    {"category": "Фотограф", "duration_hours": 6},
    {"category": "Ведущий", "duration_hours": 4}
  ]
}
```

Подсказки возвращают объект `changes`, например `{"budget_kzt":190000,"duration_hours":12}`. Для изменения одного поля также сохранены `field` и `value`.

## Проверки

```powershell
python -m unittest discover -v
node --check frontend/app.js
node --check frontend/features.js
```

Необязательный сквозной DOM-тест интерфейса (нужен Node.js 22+):

```powershell
npm install jsdom --prefix .tools/ui-test --no-save --package-lock=false --ignore-scripts
node --test tests/frontend.test.mjs
```

Тест сам запускает локальный сервер на свободном порту. Он проверяет действия пользователя и сохранение состояния, но не заменяет визуальную проверку в браузере. Тестовая библиотека находится в игнорируемой папке `.tools` и не нужна приложению.

Тесты проверяют исходный CSV, весь календарь, обязательные ограничения, реальность подсказок, пожелания и отрицания, уникальность и оптимальность команды, границы бюджета, замену каталога, API и кеш. Внешний API в тестах заменён заглушкой.

Ручная проверка: сохранить два профиля, открыть сравнение, обновить страницу и проверить избранное; выбрать дату в календаре; применить составную подсказку; собрать команду и проверить нехватку общего бюджета.

Браузерная проверка требует Playwright и установленный Google Chrome:

```powershell
python -m pip install playwright
# В другом терминале должен работать python -m backend.server
python scripts/browser_smoke.py
```

Проверяет четыре демо, карточку и компоненты оценки, применение подсказки, дробные часы и бюджет, восстановление после сетевых ошибок, отсутствие JS-ошибок, desktop 1440 px и mobile 390 px без горизонтального переполнения. Скриншоты: `artifacts/` (не включаются в git).

## Ограничения MVP

- Каталог статический, календарь заканчивается 31.12.2026. Отсутствие занятости не заменяет подтверждение подрядчиком.
- Цена «от» не является сметой. Оценка не учитывает качество работы и отзывы, которых нет в данных.
- Описания — заявления профиля, а не независимо проверенные факты. Синтетические записи помечены.
- Нет бронирований, сообщений, платежей, регистрации и редактирования каталога.
- Сервер стандартной библиотеки предназначен для локального демо. Для публичной эксплуатации нужны production-сервер, HTTPS и лимиты запросов.
