# EventMatch — умный подбор event-подрядчиков

MVP команды **WESTcoder** для HackAlem. Пользователь задаёт условия события, сервис выбирает **не больше трёх** профилей из предоставленного каталога и объясняет каждую рекомендацию.

Команда: Nurtilek Koblandy, Meirbek Arystanov, Nurkeldi Adilov.

## Быстрый запуск

Нужен **Python 3.11+**. Для работы приложения не нужны npm, сторонние Python-пакеты или API-ключ.

```powershell
cd C:\hackathon\hack-949b5db0-westcoder
python -m backend.server
```

Откройте **http://127.0.0.1:8000**. Остановка — `Ctrl+C`.

Backend и frontend обслуживаются одним процессом: REST API на `/api/*`, интерфейс на `/`. Отдельная сборка frontend не нужна. При изменениях Python перезапустите сервер; при изменениях HTML/CSS/JS обновите страницу. Другой порт: `python -m backend.server --port 8080`.

## Проблема и решение

Каталог не объясняет, кто подходит конкретному заказчику. EventMatch проверяет обязательные ограничения и показывает короткую подборку с ценой, запасом бюджета, календарём, языками, форматом, длительностью и выдержкой из индивидуального описания.

Три явных результата: `matched`, `category_not_found`, `no_candidates`. При отсутствии совпадений видны причины и предложения изменить одно условие. Подсказки не применяются автоматически.

## Архитектура

```text
CSV / JSON / JSONL
  → dataset.py: загрузка и нормализация в памяти
  → models.py: проверка запроса и правил датасета
  → filters.py: обязательные ограничения и воронка
  → semantic.py: опциональные embeddings описаний
  → scoring.py: детерминированная оценка
  → service.py: score DESC, id ASC, максимум 3
  → explanations.py: объяснения из фактов
  → relaxation.py: пересчёт альтернативных условий
  → server.py: REST API
  → frontend/: HTML, CSS, JavaScript
```

Все ограничения и числовые оценки считаются локально. Для 66 записей достаточно последовательного прохода; отдельные БД каталога и векторное хранилище не требуются. SQLite используется только для опционального кэша embeddings.

66 профилей, 17 категорий: Алматы — 50, Астана — 15, Зарубежье — 1. Синтетических профилей — 13; город проставлен у 8, цена у 18; пустой `max_hours` у 9. Цены: 100 000–6 000 000 ₸. Подробнее: [анализ датасета](docs/dataset-analysis.md).

Правила, уточнённые по приложенному PDF:

- Календарь: **2026-09-23 — 2026-12-31**. Вне окна API возвращает 422: отсутствие записи не подтверждает доступность за пределами известного календаря.
- Для `Флорист`, `Декоратор`, `Подарки и сувениры` пустой `max_hours` означает работу без почасового присутствия и не препятствует подбору с длительностью.
- Для остальных категорий неизвестный лимит не подтверждает запрошенную длительность и приводит к исключению. Без требования часов фильтр не применяется.
- Пустой список занятых дат — отсутствие занятости в пределах окна. Отсутствующий, `null` или повреждённый календарь — неизвестная доступность, кандидат исключается.
- Неизвестная цена не считается нулевой. Синтетические и проставленные значения помечены в интерфейсе.

PDF допускает добавление синтетических записей, но пользовательское задание это запрещает: используются только исходные 66 профилей.

Загрузчик поддерживает JSON (массив объектов) и JSONL. ID должны быть непустыми и уникальными. При замене `DATASET_PATH` нужно пересмотреть правила календаря и значение `null`, настроенные на исходный датасет.

## Scoring и объяснения

Фильтры: город → категория → доступность → формат → цена → длительность → язык. Сравнение строк без учёта регистра и лишних пробелов. Бюджет и часы проверяются включительно.

| Фактор | Исходный вес | Балл 0–100 |
|---|---:|---|
| Бюджет | 35 | `100 × (1 − price_from_kzt / budget_kzt)`; больший запас выше |
| Формат | 25 | 100 после обязательного фильтра |
| Язык | 15 | 100, если язык задан и пройден; иначе исключён |
| Длительность | 10 | 100, если часы заданы и пройдены; иначе исключена |
| Семантика | 15 | `100 × max(0, cosine(query_embedding, description_embedding))` |

Итог = сумма `балл × вес` / сумма **активных** весов, округление до двух знаков. Если бюджет и цена равны нулю, бюджетный компонент равен 100; в текущем CSV бесплатных профилей нет. Без embeddings их вес исключается. Балл — соответствие формуле, **не вероятность успеха и не рейтинг качества**. После фильтров формат, язык и часы не различают кандидатов; различия определяют бюджет и доступная семантика.

Сортировка: **score DESC → id ASC**, затем первые 3. В деталях карточки видны компоненты и веса. Объяснения строятся детерминированными шаблонами с индивидуальными фактами и цитатой описания. Генеративная LLM в MVP не используется, чтобы исключить новые факты и сохранить воспроизводимость.

Воронка последовательная: профиль учитывается один раз на первом непройденном условии. В подробном списке показаны все его нарушения. Прошедшие фильтры кандидаты ниже топ-3 указаны отдельно.

## AI pipeline и настройки

Опциональный семантический путь использует настоящий [OpenAI Embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create). Передаются только описания прошедших фильтры профилей и запрос из параметров события. API не может вернуть исключённого подрядчика в выдачу.

```powershell
Copy-Item .env.example .env
# В .env задайте ENABLE_EMBEDDINGS=true и свой OPENAI_API_KEY.
python -m backend.server
```

Ключ остаётся на сервере. `.env` исключён из git. Включённые embeddings обращаются к внешнему API и могут тарифицироваться провайдером.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOST` | `127.0.0.1` | Адрес сервера |
| `PORT` | `8000` | Порт |
| `DATASET_PATH` | `data/contractors.csv` | CSV / JSON / JSONL |
| `ENABLE_EMBEDDINGS` | `false` | Включить семантическое сравнение |
| `OPENAI_API_KEY` | пусто | Ключ API |
| `EMBEDDING_MODEL` | `text-embedding-3-small` | Модель embeddings |
| `CACHE_DIR` | `.cache` | Каталог SQLite-кэша |

Векторы кэшируются по модели и тексту. Решение семантического этапа — по модели, SHA-256 датасета и параметрам запроса. Кэшируются и отказы провайдера: повторный запрос сохраняет порядок после перезапуска. Для повторной попытки после сбоя используйте новый `CACHE_DIR`. Изменение модели, режима, датасета или кэша может изменить оценку; при неизменной конфигурации и кэше порядок воспроизводим.

Сетевой таймаут — 6 секунд. При недоступности API, отсутствии ключа или ошибке кэша выполняется подбор без семантики. UI показывает фактический режим. Реальный провайдер без пользовательского ключа не проверялся; успешные ответы, сбои, повреждённые векторы и кэш покрыты тестами с подменой транспорта.

## REST API

- `GET /api/health` — состояние и число профилей.
- `GET /api/meta` — параметры, статистика и демо.
- `POST /api/recommend` — подбор; `Content-Type: application/json`.

Пример PowerShell:

```powershell
$eventBody = @{
  city = 'Алматы'
  date = '2026-09-26'
  event_format = 'свадьба'
  category = 'Фотограф'
  budget_kzt = 600000
  duration_hours = 6
  language = 'русский'
} | ConvertTo-Json
Invoke-RestMethod http://127.0.0.1:8000/api/recommend -Method Post -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($eventBody))
```

Ответ содержит `status`, `message`, `request`, `total_candidates` (в городе и категории), `eligible_candidates`, `recommendations`, `filter_stats`, `excluded_reasons`, `excluded_candidates`, `suggestions`, `semantic_mode`, `dataset_sha256`. В рекомендации — поля профиля, `name`, `category`, `score`, `score_breakdown`, `reasons`, `warnings`, `explanation`.

Ошибки: 400 — повреждённый JSON; 413 — пустое или слишком большое тело (лимит 16 KiB); 415 — неправильный Content-Type; 422 — ошибки полей. Неизвестный город/категория даёт `category_not_found`. Опциональные язык/часы можно пропустить или передать `null`. Отрицательный/бесконечный бюджет, boolean вместо числа и несуществующая дата отклоняются.

## Ограничения MVP

- Каталог статический, календарь заканчивается 31.12.2026. Отсутствие занятости не заменяет подтверждение подрядчиком.
- Цена «от» не является сметой. Оценка не учитывает качество работы и отзывы, которых нет в данных.
- Описания — заявления профиля, а не независимо проверенные факты. Синтетические записи помечены.
- Нет бронирований, сообщений, платежей, регистрации и редактирования каталога.
- Сервер стандартной библиотеки предназначен для локального демо. Для публичной эксплуатации нужны production-сервер, HTTPS и лимиты запросов.
